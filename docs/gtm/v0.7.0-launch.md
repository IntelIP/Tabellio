# Tabellio v0.7.0 GTM Launch Contract

Status: Release candidate

## Objective

Give GitHub-centered teams using coding agents a credible way to answer what
changed, why it changed, which evidence applies to the exact code under review,
and which required proof is missing.

## Initial customer

Small engineering teams that already use GitHub pull requests and AI coding
agents, need stronger review traceability, and can run Node.js, Git, and local
PostgreSQL on a trusted worker.

## Positioning

Tabellio is the local evidence and review control layer for agentic development.
It does not replace GitHub, CI, Plane, or an agent runtime. It joins their bounded
facts to an exact Git candidate and refuses to call weak or mismatched evidence
a pass.

## First offer

An installable open-source package plus one repeatable provenance demo. A user
should be able to install Tabellio, inspect its version, run the demo, observe a
passing current candidate, and observe a moved candidate block stale evidence.

## Launch gates

- Package, changelog, release notes, and runner identity all say `0.7.0`.
- `npm run check` passes on the exact candidate.
- Provenance demo passes its happy path and negative failure matrix and proves
  cleanup.
- Required security scanners run; missing scanners block instead of skipping.
- `npm pack --dry-run --json` includes every runtime, schema, migration,
  validator, example, release-note, and data-boundary file required by the
  documented workflow.
- Candidate tarball installs in a clean external project and the packaged CLI
  reports `0.7.0` without attributing the consumer repository as Tabellio
  source.
- Exact merged-head validation and fresh review pass.
- Annotated `v0.7.0` tag and GitHub release point to the approved merged commit.
- npm returns public version `0.7.0`; clean external install succeeds.

## GTM proof

Recruit three to five design partners from the initial customer profile. For
each partner, record:

- time from install to first review packet;
- whether the exact candidate and missing evidence were understandable;
- whether the moved-candidate negative case changed a review decision;
- setup blocker and unsupported environment;
- decision to continue, stop, or request one bounded improvement.

Initial success means three partners independently complete one evidence-backed
pull request and at least two choose to run Tabellio again. These are targets,
not current traction claims.

## Non-goals

- Web dashboard, hosted control plane, enterprise SSO, billing, or multi-tenant
  storage.
- Automatic merge, deployment, or model self-modification.
- Compliance, security, provenance, or model-quality certification claims.
- Broad paid acquisition before the design-partner workflow works.

## Rollback

If the public package fails the documented workflow, stop promotion, deprecate
the affected npm version, publish a corrected patch through the same gates, and
keep failure evidence visible. Do not silently retag or rewrite a published
release.

## Stop condition

Do not expand scope after the package, demo, and three-partner learning loop are
working. Start another bounded phase only from observed adoption blockers.
