# Tabellio v0.7.0

## 2026-09-13

Tabellio v0.7.0 gives GitHub-centered engineering teams a local, inspectable
evidence trail for AI-assisted pull requests. It combines the v0.6.0 runner
identity contract with the TAB-18 through TAB-29 provenance, security, and
review rebuild.

## User-visible changes

- Import bounded evidence from Git, Entire, Plane, GitHub, Buildkite,
  validation, and security checks into a local PostgreSQL provenance store.
- Rebuild deterministic lineages after a database restart without changing the
  resulting digest.
- Produce a review packet scoped to the exact base, head, and merge-base under
  review.
- Keep missing, stale, conflicting, tampered, failed, and unavailable evidence
  visible instead of converting it into a pass.
- Produce separate review and security verdicts suitable for a bounded GitHub
  status update.
- Identify the Tabellio runner by package version, exact source commit, source
  cleanliness, and a verified release tag when those facts are available.

## First useful workflow

```bash
npm install --save-dev @intelip/tabellio@0.7.0
npx tabellio-version --expect-version 0.7.0
npm run tabellio:provenance:demo
```

The source demo requires Node.js 20+, Git, and local PostgreSQL client/server
binaries. It creates only temporary synthetic data, restarts its private local
database, exercises happy and negative paths, then removes its temporary files.

## Compatibility

- Existing validation-result v0.1, v0.2, and v0.3 documents remain readable.
- Validation-result v0.4 adds runner identity without changing older readers.
- GitHub remains the canonical code and pull-request authority.
- Entire remains the checkpoint/session authority; Tabellio stores bounded
  references and derived evidence, not raw prompts, transcripts, or secrets.

## Known limits

- No web dashboard or hosted multi-tenant service is included.
- The demo uses synthetic provider observations; it is not live-provider,
  security, or compliance certification.
- Production deployment, control-ref publication, GitHub release creation, npm
  publication, and external customer contact remain separately authorized.
