# WritSet v0.7.1 package migration

This release target lets users install WritSet under its own name:
`@intelip/writset@0.7.1`. npm package names are lowercase. The product name remains
**WritSet**.

These instructions apply after publication. The existing
[`@intelip/tabellio@0.7.0` release](v0.7.0.md) remains available meanwhile.
Renaming source metadata does not rename or remove that published package.

## Migrate an existing installation

In the consumer repository, replace the dependency:

```bash
npm uninstall @intelip/tabellio
npm install --save-dev @intelip/writset@0.7.1
npx writset-version --expect-version 0.7.1
npx writset-provenance-demo
```

The version receipt must report `packageName: "@intelip/writset"` and
`packageVersion: "0.7.1"`. Install one package at a time: both packages expose the
legacy command names, so keeping both can make those commands resolve ambiguously.

## Compatibility

- Every `writset-*` command uses the same implementation as its `tabellio-*` alias.
- Existing `.tabellio/` data, `tabellio.*.json` configuration, environment variables,
  Git refs, and schema identifiers keep their names. No data migration is required.
- New validators accept both WritSet and historical Tabellio package identities.
  Upgrade older validators before asking them to read WritSet-labeled results.
- Existing releases, tags, checkpoints, and stored receipts are not rewritten.

## Verification and publication

Verify package identity, both command names, a clean consumer installation, the
documented demo and cleanup, and rejection of unrelated runner identities. Run
the required repository checks and committed product-validation gate.

Merge, release-tag creation, and npm publication require their own approval.
No old-package deprecation or removal is included in this change.
